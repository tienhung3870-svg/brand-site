Building the SEO Topic Cluster Planner: Architecture, Automated Tests, and 3 Keyword Inputs

By Hung Pham · October 2026 · Live Demo ↗

1. Why I Built It

Planning content for search engines usually starts in a chaotic spreadsheet. Writers and strategists list target keywords, guess internal linking structures, and paste URLs into rows without any way to see how articles actually connect. Traditional SEO suites solve part of this, but they come with heavy baggage: costly monthly subscriptions, closed ecosystems, and the requirement to upload confidential editorial roadmaps to external third-party databases months before publication.

I wanted a specialized, local-first browser tool where creators can visually construct topic clusters, enforce internal linking architectures (Pillar ↔ Spoke, parent ↔ child), and evaluate keyword potential—helping avoid unintended leakage of unpublished editorial roadmaps.

Key design principles from day zero:

  • Local-First Project Storage: By default, project data is stored in the browser's IndexedDB. Optional Supabase features can sync or share a project when the user configures cloud access and explicitly uses those controls. Keyword research sends the requested terms to configured research endpoints.
  • Structural Integrity: Enforce link validation rules (detecting circular parent-child dependencies, warning about missing links to children, and ensuring self-canonical hygiene) before copy is drafted.
  • Interactive Visualization: An interactive visual graph canvas capable of rendering multi-tier topic topologies with automated layout.

The result is the SEO Topic Cluster Planner, deployed on Cloudflare Pages with client-side persistence by default and zero requirement for cloud logins to start planning.

2. The Stack

The architecture was chosen to balance client-side responsiveness, type safety, and a client-first design with optional serverless edge and cloud services:

Layer Technology Rationale
Framework & Build Vite + React 19 (19.3.0) + TypeScript Fast HMR during development, production builds, and typed domain models.
Interactive Canvas @xyflow/react (React Flow 12.12.0) + Dagre Node-based canvas for exploring topic clusters, paired with Dagre's directed graph layout engine for automated hierarchical arrangement.
State & Commands React State + Command Engine UI state uses React hooks; document mutations pass through a typed command layer with bounded undo/redo history (src/application/commands.ts).
Schema & Validation Zod 4 (4.6.5) Runtime schema parsing for ProjectDocument, Article, InternalLink, and ValidationIssue. Catches corruption and schema drift before persistence.
Persistence IndexedDB via idb 8.0.3 Client-side storage supporting versioned snapshot backups, JSON export/import, and offline recovery.
Edge Functions Cloudflare Pages Functions Serverless proxy endpoints (/api/suggest, /api/paa, /api/bing) handling rate limiting, CORS headers, and secure API key isolation.
Testing Vitest 5.0.1 + Playwright 1.63.0 Vitest unit tests with an optional V8 coverage command, paired with browser-level end-to-end test definitions.

3. Automated Test Verification: 290 Passed Unit Tests & 23 Defined E2E Scenarios

Because the application manages directed acyclic graph (DAG) invariants, link checklists, and multi-source keyword math, automated test suites verify these interface contracts across core domain units.

Unit & Domain Test Suite (290 Tests in 24 Test Files)

The unit test suite covers core domain mechanics across 24 test files (290 passed tests executed via Vitest):

  • URL & Domain Invariants: Strict HTTP(S) validation, preventing domain mismatches, rejecting malformed userinfo inputs, and validating canonical rules.
  • Graph Topology & Structural Checks: Automated cycle detection, hierarchy tier calculation (Pillar = Tier 1, child = parent depth + 1), and validation of missing parent-to-child reciprocal links.
  • Merge Algorithms & Scoring: Comprehensive testing of keyword deduplication, provenance tracking, and confidence score calculation.
  • Edge Functions & Parsers: Unit tests verifying JSON and XML response parsers for Google Autocomplete, People Also Ask (PAA), and Bing Webmaster API endpoints under varying network payloads and HTTP status codes.

Browser End-to-End Suite (23 Playwright Scenarios in 12 Spec Files)

The repository defines 23 Playwright E2E scenarios across 12 spec files designed to cover end-to-end user workflows in Chromium browser environments:

  1. Keyword Research & CSV Import: Uploading CSV keyword batches, inspecting provenance, and asserting table rendering.
  2. Interactive Canvas Operations: Adding articles, connecting edges, expanding/collapsing subtrees, and triggering automated Dagre re-layouts.
  3. Multi-Source Keyword Research Panel: Submitting queries, viewing multi-source metrics, inspecting provenance drawers, and exporting aggregated CSVs.
  4. Validation Checklist & Issues Drawer: Triggering structural warnings and verifying interactive resolution links.
  5. Brief & Markdown Export: Generating and downloading formatted article briefs and content guidelines.
  6. Cloud Fallback & Offline Resilience: Testing graceful degradation when cloud backend services are unavailable or unconfigured.

These 23 E2E test scenarios are structured to run against preview builds with mocked external network endpoints.

4. Three Keyword Research Inputs

Search volume from a single source is often incomplete or delayed. To assist editorial decision-making while keeping project files local, the planner integrates three keyword research inputs (two serverless edge endpoints and one offline CSV importer):

1. Google Suggest (Autocomplete Proxy)

Queried via /api/suggest through Cloudflare Pages Functions. The endpoint proxies Google autocomplete query completion and prefix expansion patterns for long-tail discovery. Upstream reachability depends on Google's suggestion endpoint availability; responses are validated at request time and subject to upstream network limits.

2. Google Trends (Exported CSV Ingestion Only)

Google Trends data is ingested strictly from user-exported CSV datasets (via src/features/keywords/sources/trends.ts), not through a live API call. The client-side parser reads exported timeline rows and computes relative interest momentum locally without third-party scraping.

3. Bing Webmaster Proxy (Cloudflare Pages Functions)

Implemented in functions/api/bing.ts. To prevent exposing private credentials in client-side code, Cloudflare Pages Functions provides an authenticated proxy handler:

  • Connects to the Bing Webmaster API when configured with a server-side BING_WEBMASTER_API_KEY or an optional self-hosted proxy (BING_PROXY_URL).
  • Enforces IP-based rate limiting (10 requests per minute per IP via functions/lib/http.ts).
  • When credentials or backend proxies are unconfigured, the endpoint returns an HTTP 502/503 status, signaling the client-side UI to fall back cleanly to local CSV or suggestion data.

The Multi-Source Heuristic Merge Engine

The core logic in src/features/keywords/merge.ts unifies these feeds into an actionable consensus:

  • Base Weighting: Bing direct query counts receive a high baseline weight (0.8).
  • Relative Trends Score: Trends-only signals receive a relative confidence weight (0.4).
  • Co-occurrence Boost: Keywords confirmed by both Autocomplete and Trends (score > 30) are boosted to 0.6 and flagged as likely_searched.
  • Automated Disagreement Flagging: If Bing indicates zero volume while Google Trends indicates high momentum (> 50), the system flags a disagreement, prompting human editorial review rather than masking the discrepancy.

5. Lessons Learned

Building and testing this tool surfaced several non-obvious engineering challenges:

Lesson 1: Cache Hygiene and Failure Handling

Successful keyword payloads are cached in IndexedDB. A Bing 503 returns an unknown result without caching a keyword measurement, allowing subsequent queries to re-attempt upstream requests when credentials are restored. People Also Ask (PAA) failures use separate, bounded retry metadata so the client can avoid hammering an unavailable upstream.

Rule established: Keyword cache entries require successful responses, while upstream error states remain short-lived or use bounded backoff metadata.

Lesson 2: Build-Time Environment Leakage into Preview Bundles

During local development, vite build bundled environment variables from .env.local into the production output bundle. When Playwright launched vite preview to run the cloud-fallback.spec.ts test (which asserts that the UI shows appropriate fallback messaging when cloud sync is unconfigured), the test unexpectedly failed because the app detected the baked-in credentials and considered itself configured.

Fix: We decoupled E2E testing into a dedicated test mode that guarantees an empty environment configuration, ensuring offline and fallback assertions remain reproducible.

Lesson 3: Mocking External Endpoints in Browser Scenarios

Relying on live external search engine APIs during CI or automated browser checks can lead to throttling and non-deterministic results. The Playwright E2E scenarios use page.route to mock edge API responses with realistic fixtures, isolating browser workflow checks from external network dependencies.

6. What's Next

The tool is live at seo-topic-cluster-planner.pages.dev. Possible next steps include expanding keyword provenance filters and adding deeper content brief export templates.
